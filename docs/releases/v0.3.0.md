# Kafka Lens v0.3.0

发布日期：2026 年 11 月 1 日

本版本将部署包拆分为三个独立平台包，新增 Linux ARM64 支持，并加入完整的 Release 附件核验流程。

## 更新清单

- 支持 Linux AMD64、Linux ARM64、Apple Silicon macOS 三种独立半离线部署包，每包包含对应后端、前端静态资源、启动器和配置模板。
- 打包必须显式指定 `--platform linux-amd64|linux-arm64|darwin-arm64`，每次只生成一个平台，不再同时生成多个平台。
- 两种 Linux 架构使用 `cargo zigbuild --release` 编译到对应 musl target；macOS ARM64 在 Apple Silicon 上原生构建。
- 每个归档附带 SHA-256 校验文件，包内提供完整文件校验清单和版本、平台、提交来源记录。
- 构建失败保留原有产物；已有 `.env` 或 `data/` 的部署目录禁止覆盖；构建期间源码变化会使打包失败。
- GitHub Actions 分别构建并运行验收三个平台，全部成功后汇总六个附件。Release 保持草稿，直到附件上传、重新下载与字节比对全部成功。
- 强化归档内容、二进制架构和结构校验；修复 Linux 验收容器与宿主用户身份不一致导致的数据目录权限问题。

## 部署与升级

以 Linux AMD64 为例，将归档和校验文件放在同一目录：

```bash
sha256sum -c kafka-dashboard-v0.3.0-linux-amd64.tar.gz.sha256
tar -xzf kafka-dashboard-v0.3.0-linux-amd64.tar.gz
cd kafka-dashboard-v0.3.0-linux-amd64
cp .env.example .env
chmod 600 .env
./start.sh
./start.sh status
```

macOS 可用 `shasum -a 256 -c` 校验。默认访问 `http://127.0.0.1:3000`，使用 `./start.sh stop` 正常停止。

从 v0.2.0 升级时，先停止旧服务并备份 `.env`、`data/`，将它们以原有私有权限复制到新的平台目录后启动；无需数据库迁移。不要覆盖仍在运行的目录。SQLite 含明文凭据，服务没有内置认证，请沿用受控内网或带认证反向代理的部署方式。
