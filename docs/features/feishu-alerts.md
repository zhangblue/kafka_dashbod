# 飞书 Lag 增长告警

先在飞书群中添加自定义机器人，从 Webhook 中复制 `access_token` 对应的 Token 值，在「集群设置」的对应集群卡片点击「配置飞书告警」。只填写 Token，不要粘贴完整 Webhook URL；Token 按集群独立保存，规则按 Consumer Group + Topic 配置，同一组合只能有一条规则，与页面的正常/高 Lag 展示规则相互独立。

「更新 Token」默认隐藏，眼睛图标只切换当前输入值的可见性；保存后清空输入，重开只显示已保存 Token 的掩码，留空保存表示保留。点击「测试通知」可使用当前新输入值或已保存 Token 发送测试消息；测试不保存草稿。若显示失败，请核对机器人 Token、群设置以及服务端到飞书 HTTPS 的网络。成功提示表示飞书接口接受请求，应同时在目标群确认消息。

## 告警条件

新增规则时从真实快照选择 Consumer Group 和该组有提交位置的 Topic，填写非负整数 Lag 阈值（最小 0）、持续时间（整数且至少 10 秒），勾选启用后保存。阈值比较的是该 Group 在此 Topic 的所有 Partition Lag 总和，严格超过阈值才开始计时。完整、有效的连续采样必须在持续时间内非递减，且至少发生一次实际增长；持平可保留已有增长证据，但全程持平不会触发。Lag 下降时从当前样本重新计时；任一 Partition 未知、未提交、采集失败或陈旧，均不以部分总和告警，并中断增长计时。

## 后台采集与重试

后台每 5 秒采样。配置 Token 且至少有一条启用规则的集群，会保持独立的只读 Kafka 连接；浏览器关闭、页面隐藏或切换集群后仍监控。无 Token 或无启用规则的集群不发送告警、不保持后台连接。规则只读取 Kafka，不提交 Offset、不修改 Topic；浏览器会话仍按短租约单独释放。

每条规则的每轮超限最多成功通知一次。发送失败后从结果返回起至少等待 30 秒，且只有完整有效采样仍满足增长条件时重试；含首次发送总计最多 3 次，第三次失败后停止本轮尝试。只有完整有效的总 Lag 恢复到小于或等于阈值，才重新允许下一轮通知；下降但仍超限、未知或失败样本均不会解除已通知/重试耗尽的状态。修改规则或 Token、服务重启会重建内存判定状态，不保存历史计时。

停用时取消规则的「启用规则」并保存，或删除规则后保存；清除时勾选「清除已保存 Token」并保存，摘要变为「未配置」，全部规则停止发送。**Token 与 Kafka 凭据一样以明文保存在 SQLite**；限制数据库、`-wal` / `-shm` / `-journal` sidecar、备份及 `.env` 的读取权限，不在日志、截图、trace 或故障附件中保存 Token、通知请求体或响应正文。服务无内置认证，必须按[部署指南](../guides/deployment.md)控制全部 HTTP/API 访问；不要把通知配置接口暴露到公网。
