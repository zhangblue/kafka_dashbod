# Kafka Lens 中英文国际化设计

## 目标

为 Kafka Lens 前端增加中文与 English 即时切换能力。首次访问跟随浏览器语言，用户主动切换后记住选择。语言切换覆盖全部用户可见界面与安全错误提示，同时不改变 Kafka 会话、采样、Topic 管理、告警和持久化行为。

## 范围

本次包含：

- 左侧导航、所有顶部栏、页面标题与说明；
- 概览、Topics、Consumer Groups、集群设置页面；
- Topic 新建、删除、参数配置弹窗；
- Lag 规则、飞书告警与集群连接表单；
- 表格、状态标签、按钮、字段说明、空状态、加载状态、确认提示；
- `aria-label`、`title`、输入占位符和图表文本；
- 前端表单校验、已知 API 错误、字段错误与安全通用错误；
- 日期、时间和数字的当前语言格式化。

本次不包含：

- 后端接口或 SQLite 结构变更；
- 服务端保存用户语言；
- 运行时下载翻译资源；
- 中文、English 以外的语言；
- 翻译 Kafka 专有术语、品牌、集群名或用户配置内容。

## 术语规则

`Kafka Lens`、`Topic`、`Consumer Group`、`Lag`、`Offset`、`Partition`、`Broker`、`Bootstrap Servers`、`SASL`、`SSL`、`PEM`、`Request ID` 等技术术语在中英文界面中保留英文。普通说明、操作、状态与错误文案随语言切换。用户输入的名称与 Kafka 返回的资源标识原样显示。

## 技术方案

使用 `i18next` 与 `react-i18next`：

- `frontend/src/i18n/` 负责初始化、语言类型、语言解析和资源导出；
- 中文与英文资源随前端 bundle 打包，不发送额外 HTTP 请求；
- React 组件通过 `useTranslation` 读取文案；
- 翻译资源保持类型化，并通过测试保证两种语言的键集合一致；
- React 已负责文本转义，i18next 插值不重复转义。

不采用自研 React Context 字典，避免自行维护插值、复数、缺失键检查和扩展能力；不采用需要额外提取与编译流程的 Lingui，避免为双语需求引入过重工具链。

## 语言解析与持久化

语言解析顺序如下：

1. 若 `localStorage` 中存在有效的用户选择，使用该选择；
2. 否则读取 `navigator.languages` 与 `navigator.language`；
3. 浏览器语言以 `zh` 开头时使用 `zh-CN`，其他情况使用 `en`；
4. 无法读取浏览器或存储时安全回退到 `zh-CN`。

用户点击语言切换后立即调用 i18next 的语言切换能力，并将明确选择写入本地存储。切换不刷新页面。每次语言生效时同步设置文档根节点的 `lang` 为 `zh-CN` 或 `en`。清除对应本地存储后，下次加载重新跟随浏览器。

本地存储只保存固定语言枚举，不保存集群、凭据或业务数据。存储不可用时仍允许当前页面切换，只是不持久化。

## UI 与交互

新增公共 `LanguageSwitch` 组件，采用已确认的方案 A：

- 位于所有页面顶部栏最右侧；
- 桌面显示“中文 / EN”；
- 窄屏保留紧凑的“中 / EN”表现，但可访问名称使用完整语言名称；
- 当前语言具有明确的视觉选中状态和 `aria-pressed` 状态；
- 支持 Tab 聚焦、Enter 与 Space 激活；
- 风格沿用已确认 Dashboard Demo 的深色边框、紧凑间距与选中背景。

监控页面在刷新按钮之后放置语言控件。集群设置顶部栏也复用同一组件。语言切换只触发文本重渲染，不改变路由、当前集群、刷新频率、Kafka 会话、采样连续性、弹窗开关、表单草稿或最近一小时内存历史。

## 翻译资源组织

资源按稳定语义分区，例如：

- `common`：通用按钮、状态、时间单位和安全错误；
- `navigation`：品牌说明、导航与顶部栏；
- `overview`、`topics`、`consumerGroups`、`clusters`：各页面；
- `lagRules`、`feishuAlerts`：配置功能；
- `topicAdmin`：Topic 管理弹窗；
- `apiErrors`、`validation`：API 与字段错误。

翻译键描述语义而不是直接使用中文原文，避免文案修改导致键名变化。带数字、名称和时间的文本使用插值；数量变化使用 i18next 复数规则。技术术语作为资源值的一部分保留英文。

## 日期、时间与数字

格式化函数从当前语言派生 locale：中文使用 `zh-CN`，英文使用 `en`。页面展示时间、日期和需要分组的数字时使用 `Intl.DateTimeFormat` 或 `Intl.NumberFormat`。Kafka Offset、Lag 等整数不改变数值语义；仅允许本地化分组符号。机器字段、配置值与 API 请求仍使用原格式。

## 错误处理

前端不直接把后端 `message` 当作最终用户文案：

- 已知 `ApiError.code` 映射到 `apiErrors` 翻译键；
- 已知字段校验按受控校验类别映射到 `validation` 翻译键；
- 无法识别的顶层错误显示“请求失败，请稍后重试 / Request failed. Please try again later.”；
- 无法识别的字段错误显示“字段值无效 / Invalid value”；
- `Request ID` 继续显示，字段的 `aria-describedby` 关系保持不变；
- Kafka 原生错误、请求正文、凭据、PEM 与服务端内部细节不得进入翻译插值或页面。

错误翻译仅发生在展示层。业务逻辑继续依赖 HTTP 状态和稳定错误码，不依赖本地化文案。现有后端安全错误结构不变。

## 测试策略

遵循 TDD，先补失败测试，再做最小实现。覆盖：

- 无用户选择时按浏览器语言选择中文或英文；
- 有用户选择时覆盖浏览器语言；
- 切换后写入本地存储并同步 `<html lang>`；
- 存储读取或写入失败时安全回退；
- `LanguageSwitch` 的选中状态、键盘操作和窄屏可访问名称；
- 中英文资源键集合完全一致，缺失键时测试失败；
- 主要页面、弹窗、状态、图表和辅助文本能切换；
- API 顶层错误、字段错误、未知错误和 `Request ID` 的双语展示；
- 切换语言后当前路由、集群、会话、刷新频率、表单草稿、弹窗和内存历史保持不变；
- 生产构建与现有全部前端回归继续通过。

现有业务测试默认固定中文，避免将整套用例重复执行两遍。新增针对性英文测试验证关键流程和翻译覆盖。E2E 至少验证一次从中文切换 English 后，导航、当前页面和一个弹窗同步切换且监控会话未重建。

## 验收标准

- 浏览器首次打开按语言自动显示中文或 English；
- 用户选择在后续访问中保持；
- 顶部栏语言入口符合已确认方案 A，桌面与窄屏均可用；
- 所有正式页面、弹窗、状态、辅助文本和安全错误均无混入另一语言的普通文案；
- Kafka 专有术语与用户数据保持原样；
- 切换不刷新页面、不重连 Kafka、不清空任何当前 UI 状态；
- 未知后端错误不会回显后端原文或敏感信息；
- 翻译资源完整性、前端单元测试、E2E、类型检查和生产构建通过。
