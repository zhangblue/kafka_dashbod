# Kafka Lens 启动时强制加载 `.env` 设计

## 背景与目标

当前 Rust 程序只读取进程环境变量，发行启动器 `start.sh` 会为数据库和前端静态目录设置默认环境变量；程序和启动器都不会读取 `.env`。本次修改将配置加载职责收敛到 Rust 程序：正常启动服务时必须从当前工作目录加载 `.env`，发行启动器不再设置、导出或解析任何配置参数。

成功标准：

- 正常启动服务时，当前工作目录必须存在可读取且格式正确的 `.env`，否则程序以非零状态退出并给出不包含配置值的错误。
- Rust 在读取应用配置和初始化日志之前加载 `.env`。
- 父进程已经设置的环境变量优先于 `.env` 中的同名变量；`.env` 只补充尚未设置的变量。
- `start.sh` 不读取 `.env`，也不设置或导出 `DATABASE_URL`、`KAFKA_DASHBOARD_WEB_DIR`、`KAFKA_DASHBOARD_BIND`、`RUST_LOG` 等配置。
- 打包产物中的 `README.txt` 使用中文，并说明配置、运行、安全和常见故障处理方法。

## 方案选择

采用 `dotenvy` 作为 Rust 运行时依赖，在进程入口调用其标准 `.env` 加载 API。该库提供成熟的 `.env` 解析规则，并默认保留父进程中已存在的同名环境变量。

不自行实现解析器，避免重复处理引号、转义和格式错误等边界。不由 `start.sh` 使用 shell `source` 加载文件，因为这既不满足由 Rust 负责加载的目标，也会引入与 `.env` 格式不完全一致的 shell 解析语义。

## 启动流程

正常服务启动流程调整为：

1. 判断是否为 `--version` 请求；若是，打印版本并退出，不要求 `.env`。
2. 从进程当前工作目录查找并加载 `.env`。
3. `.env` 不存在、不可读或解析失败时，将安全错误转换为启动错误并退出；错误不得包含变量值或其他秘密。
4. 初始化日志订阅器。
5. 通过现有 `Config::from_env` 和监听地址读取逻辑获取合并后的环境变量。
6. 初始化数据库、静态资源、API 和监听器。

`.env` 必须存在，但其中的每个配置项仍遵循现有可选性与默认值。也就是说，空的、但格式合法的 `.env` 可以启动；`DATABASE_URL` 和 `KAFKA_DASHBOARD_BIND` 未配置时仍使用 Rust 当前内置默认值，`KAFKA_DASHBOARD_WEB_DIR` 未配置时仍只提供 API。发行使用场景将在 `.env.example` 中给出适合发行目录的显式配置。

## 发行启动器

`packaging/start.sh` 保留以下职责：

- 根据操作系统和 CPU 架构选择二进制。
- 将工作目录切换到发行目录，使 Rust 从发行目录读取 `.env`，相对路径也以发行目录为基准。
- 设置私有权限掩码并创建 `data/` 目录。
- 使用 `exec` 启动二进制并原样传递命令行参数。

启动器删除 `DATABASE_URL` 和 `KAFKA_DASHBOARD_WEB_DIR` 的默认赋值及 `export`。它不会解析、验证或修改 `.env`。

## 配置示例与中文发行说明

`packaging/.env.example` 改为可复制的配置模板，不包含真实秘密。模板说明外部环境变量优先于文件值，并至少展示：

- `KAFKA_DASHBOARD_BIND`
- `DATABASE_URL`
- `KAFKA_DASHBOARD_WEB_DIR`
- `RUST_LOG`

打包产物继续使用文件名 `README.txt`，但内容全部使用中文，至少包括：

- 支持的平台和运行前提。
- 将 `.env.example` 复制为 `.env` 并按需修改的操作步骤。
- 各配置项的用途、发行目录适用的示例值和相对路径基准。
- 使用 `./start.sh` 启动、使用 `./start.sh --version` 查看版本，以及停止程序的方法。
- 默认访问地址与健康检查地址。
- `.env` 缺失、不可读或格式错误时的失败行为。
- 外部环境变量覆盖 `.env` 同名配置的优先级。
- SQLite 明文凭据、`.env`、数据库及 sidecar 文件的权限和备份安全提醒。
- 旧数据库升级步骤和常见启动故障排查。

仓库根目录 `README.md` 同步更新源码运行、环境变量和发行运行说明，删除“不会自动读取 `.env`”的旧描述。

## 错误处理与安全

- 缺少 `.env` 和 `.env` 解析错误必须阻止正常服务启动。
- 错误消息可以指出文件路径或错误类型，但不得回显整行配置、变量值、Kafka 凭据、PEM 或数据库内容。
- `--version` 不进入配置加载流程，保持离线发行校验和版本查询可用。
- 现有 API、日志脱敏、请求大小及凭据存储边界不变。

## 测试与验证

修改遵循 TDD，先增加能因功能缺失而失败的进程级或配置级测试，再进行最小实现。覆盖：

1. 当前工作目录缺少 `.env` 时，正常启动以非零状态退出。
2. Rust 从 `.env` 读取数据库、静态目录或监听配置并成功应用。
3. 父进程环境变量覆盖 `.env` 中的同名变量。
4. `.env` 格式错误时启动失败，输出不泄漏测试秘密。
5. `--version` 在没有 `.env` 时仍成功。
6. `start.sh` 不再注入数据库或静态目录配置，并继续传递参数、选择平台和保持发行目录工作路径。
7. 构建出的发行文件仍包含 `.env.example` 和中文 `README.txt`。

至少运行相关 Rust 进程测试、发行脚本测试、格式检查和差异检查；根据变更影响再运行工作区测试与发行构建验证。任何受平台或环境限制而未运行的检查都需明确记录。
