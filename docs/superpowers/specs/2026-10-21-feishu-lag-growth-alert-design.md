# 飞书 Lag 持续增长告警设计

## 背景与目标

Kafka Lens 当前只在页面可见时按需采样，未提供通知渠道。新增后端常驻告警监控：用户可为每个 Kafka 集群配置飞书自定义机器人 `access_token` 和独立的持续增长时间；当某个 Consumer Group / Topic 的 Lag 超过生效规则的正常上限、持续不下降且实际发生增长达到配置时长后，向对应飞书群发送一次明确通知。未配置 Token 的集群不建立告警监控，也不发送消息。

本功能不保存指标历史，不生产 Kafka 消息，不提交或重置消费位置，也不改变页面内存历史和页面短租约的语义。

## 已确认的产品行为

- 后端常驻监控，不依赖浏览器页面是否打开。
- 飞书配置按 Kafka 集群隔离，不提供全局默认配置。
- 只支持飞书自定义机器人 Webhook 的 `access_token`。请求目标固定为飞书官方机器人接口，不允许用户配置任意 URL；本期不支持飞书应用凭据或机器人签名密钥。
- 告警持续增长时间为独立的集群级配置，不复用 Lag 页面状态规则中的持续超限时间，默认值为 60 秒。
- 后台采样周期固定为 5 秒，本期不开放配置。
- 每轮异常只成功通知一次；只有 Lag 恢复到正常上限以内后，下一轮异常才可再次通知。
- 真实通知失败后每隔 30 秒重试，最多 3 次。成功后停止重试；3 次均失败后，本轮异常不再发送。
- 页面提供“发送测试通知”，可使用当前新输入的 Token；编辑时未输入新 Token 则使用已保存值。

## 页面与交互

集群卡片新增独立的“配置飞书告警”入口，不把通知设置混入 Kafka 连接表单。卡片摘要显示以下状态之一：

- `飞书告警：未配置`
- `飞书告警：已启用 · 持续增长 60 秒后通知`

弹窗包含：

- 飞书机器人 Token 密码输入框；
- “显示 Token”复选框，仅切换本次新输入内容的可见性；
- 已保存 Token 的掩码提示，例如 `••••••••a1b2`；
- “清除已保存的 Token 并停用通知”复选框；
- 持续增长时间（秒），非负安全整数；
- “发送测试通知”“取消”“保存”操作。

完整的已保存 Token 永不返回前端。编辑时 Token 留空表示保留；新值与清除操作不能同时提交。测试通知优先使用当前输入的新 Token，新 Token 为空时使用已保存值。没有任何可用 Token 时禁用测试操作并给出中文提示。

页面沿用 `docs/ui/approved-dashboard-demo.html` 的布局、字体、间距、配色、边框和弹窗样式。

## 数据模型与安全

新增集群飞书告警设置表，建议字段如下：

- `cluster_id`：主键和外键，引用集群并在删除集群时级联删除；
- `access_token`：明文 Token；
- `growth_seconds`：持续增长时间，非负整数，默认 60；
- `created_at`、`updated_at`。

Token 与现有 Kafka 凭据一样属于明文敏感信息。数据库、sidecar 和备份必须限制访问权限。列表和读取接口只返回 `accessTokenConfigured`、掩码后缀和持续秒数；日志、错误响应、测试附件和浏览器 trace 不得包含 Token、飞书请求体或飞书原始响应。

后端从固定的飞书官方基地址构造 Webhook URL，并把 Token 作为单一路径段安全编码；不接受完整 URL。Token 去除首尾空白后必须非空、不包含控制字符，并设置合理长度上限。飞书请求设置固定超时，响应只映射为稳定的成功或安全错误，不向客户端透传远端响应正文。

## API

新增以下集群级接口：

### `GET /api/clusters/:id/feishu-alert`

返回：

```json
{
  "accessTokenConfigured": true,
  "maskedAccessToken": "••••••••a1b2",
  "growthSeconds": 60
}
```

未配置时 `accessTokenConfigured` 为 `false`，`maskedAccessToken` 为 `null`。接口不得返回完整 Token。

### `PUT /api/clusters/:id/feishu-alert`

请求字段：

```json
{
  "accessToken": "optional-new-token",
  "clearAccessToken": false,
  "growthSeconds": 60
}
```

`accessToken` 省略或为空表示保留已保存值；`clearAccessToken` 为 `true` 表示删除 Token并停用通知。两者同时存在时返回字段校验错误。成功响应与 GET 相同。

### `POST /api/clusters/:id/feishu-alert/test`

可携带可选的新 Token；新 Token 为空时读取已保存 Token。发送内容明确标记为测试消息，并包含集群名称。操作不保存配置。没有可用 Token 时返回字段校验错误。外部请求错误使用统一安全错误及 Request ID。

请求继续受全局 256 KiB 上限约束。

## 后端架构与生命周期

新增独立的 `AlertMonitor`，不复用页面会话的 15 秒短租约。应用启动后启动监控器，退出时先阻止新一轮工作，再等待已接受的 Kafka 采集、客户端释放和有界飞书请求完成。

监控器每 5 秒协调一次配置：

1. 读取配置了 Token 的集群及其最新 Kafka 连接、Lag 规则与告警设置；
2. 为每个启用集群维护一个独立任务；
3. 新增配置时启动任务；
4. Kafka 连接、Lag 规则、告警配置发生变化时，停止旧任务、清除状态并按新配置重建；
5. 清除 Token 或删除集群时，停止任务并等待资源释放。

每个集群任务持有自己的只读 Kafka 客户端，同一时刻最多执行一次采集，慢采集不重叠。任务只读取水位与已提交 Offset。配置变化和进程退出不能把阻塞原生工作或 HTTP 请求遗留到后台。

## 持续增长状态机

状态以 `cluster_id + group_id + topic` 为键。每个键维护上一有效 Lag、候选起点、是否发生实际增长、是否已成功通知、下一重试时间和重试次数。

每次采样按当前 Group + Topic 自定义规则或集群默认规则解析正常上限：

1. Lag 未知、分区不完整、对应采集失败或规则变化：清除该键的连续候选状态。规则变化同时清除已通知与重试状态，避免跨配置继承。
2. `lag <= normal_max`：视为恢复正常，清除候选、已通知和重试状态。
3. 首次观察到 `lag > normal_max`：记录当前 Lag 和单调时钟起点，尚未标记增长。
4. 后续 `lag >= previous_lag`：保持同一候选窗口；只有严格大于上一值时才标记已经发生实际增长。
5. 后续 `lag < previous_lag`：连续增长中断，以当前样本作为新的候选起点，并清除“已发生增长”标记。若本轮此前已成功通知，则仍保持已通知状态，直到恢复正常，保证每轮异常只通知一次。
6. 候选窗口达到 `growth_seconds` 且至少发生一次实际增长时触发通知。`growth_seconds = 0` 仍需两个有效样本确认实际增长，单个样本不得触发。

持续时间使用单调时钟计算，不使用 Kafka 消息时间或系统墙上时钟。进程重启、任务重建、连接中断和采集异常均重新计时，不能推断停机或不可见区间持续增长。

## 通知与重试

真实告警使用清晰的文本消息：

```text
Kafka 积压持续增长告警
Kafka 集群：订单生产集群
Topic：orders
Consumer Group：order-service
当前积压量：12,580
已连续增长：60 秒
检测时间：2026-10-21 21:30:00 +08:00
```

消息必须包含 Kafka 集群名称、Topic、Consumer Group 和当前积压量。可额外包含连续时间与检测时间，但不包含 Bootstrap Servers、Kafka 凭据、飞书 Token、分区错误详情或原始异常。

首次发送失败时保持“尚未通知”，30 秒后重试；总尝试次数最多 3 次。每次重试使用最新有效 Lag 和检测时间，同时保留原候选起点。成功后标记本轮已通知。3 次均失败后标记本轮不再发送，直到恢复正常。日志仅记录脱敏的错误类别、集群 ID、尝试次数和 Request ID。

## 错误处理

- Kafka 连接或采集失败不得产生告警；清除连续候选状态并等待后续采样。
- 单个集群失败不得阻塞其他集群任务。
- 飞书超时、网络错误、非成功 HTTP 状态或业务返回失败统一映射为安全错误。
- 后台失败不改变 API 服务可用性；配置页显示最近一次测试请求的明确结果，后台运行状态通过脱敏日志诊断。
- 修改设置成功但任务重建失败时，设置仍被保存；监控器继续按周期重试启动，日志记录安全错误。

## 测试策略

### Rust 领域测试

- 超过正常上限后严格增长、增长后持平、下降后重新计时和恢复正常；
- 未知 Lag、不完整分区、采集失败和规则变化重置；
- 持平窗口不告警；
- `growth_seconds = 0` 仍要求第二个增长样本；
- 每轮只成功通知一次；
- 30 秒间隔、最多 3 次重试和成功后停止重试；
- 进程或任务重建不继承连续状态。

### 仓储和 API 测试

- 新建、更新、留空保留、显式清除和删除集群级联；
- GET、PUT 及错误响应均不包含完整 Token；
- 掩码仅暴露有限后缀；
- Token 与清除冲突、非法时长、无可用 Token 测试等字段校验；
- 256 KiB 请求上限与统一 Request ID 保持有效。

### 飞书客户端测试

- 使用可替换 HTTP 传输验证固定官方目标、路径段编码、超时与请求格式；
- 验证真实告警的四个必填业务字段和测试消息标识；
- 验证任何远端错误都不会回显 Token、请求体或原始响应。

测试不连接真实飞书，不需要真实 Token。正式客户端仍固定为飞书官方地址；测试通过依赖注入的本地传输验证。

### 生命周期与前端测试

- 启用、更新、清除和删除配置时任务正确启动、重建和停止；
- 同一集群采集不重叠，退出等待在途工作；
- 集群卡片摘要、独立弹窗、已保存掩码、本次输入显示切换、测试发送、保存和清除；
- 页面和测试附件不泄漏 Token。

## 文档与发行

更新 README 和发行包中文 `README.txt`，说明：

- 如何在飞书群中创建自定义机器人并取得 Webhook 中的 `access_token`；
- 每集群配置、测试、启用与停用方法；
- 持续增长的精确定义、一次通知和失败重试行为；
- 后台监控会在页面关闭时继续连接 Kafka；
- Token 明文保存在 SQLite，需限制数据库、sidecar 和备份权限；
- 服务无内置认证，应部署在受保护网络或认证反向代理之后。

## 非目标

- 不支持飞书应用身份、签名密钥、交互卡片或多机器人；
- 不支持任意 Webhook URL、其他通知平台或全局通知配置；
- 不持久化 Lag 历史、连续状态、重试队列或通知记录；
- 不提供重复提醒、倍数提醒、恢复通知或静默时间段；
- 不开放后台采样周期配置。
