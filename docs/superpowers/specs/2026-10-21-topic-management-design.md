# Kafka Lens Topic 管理设计规格

## 1. 背景与目标

Kafka Lens 当前只读取 Kafka 元数据、Offset 和 Consumer Group 状态，明确禁止创建、删除或修改 Topic。本次功能经用户确认后解除 Topic 管理范围内的只读限制，使用户可以在现有 Topics 页面中：

- 创建 Topic；
- 删除非内部 Topic；
- 查看 Topic 当前实际生效的可动态修改配置；
- 修改受控白名单内的 Topic 配置；
- 删除 Topic 级配置覆盖值，恢复继承 Broker 默认值。

本次变更只增加 Topic 管理能力，不增加消息生产、消息删除、Consumer Group Offset 重置、Topic 分区扩容、分区副本重分配或 Broker 配置修改能力。

## 2. 已确认的产品方案

Topics 页面沿用已确认的紧凑表格布局，不新增独立管理页面：

- 页面工具栏增加“新建 Topic”按钮；
- 每个非内部 Topic 行增加“配置”和“删除”操作；
- `__` 开头的 Kafka 内部 Topic 不显示删除入口；
- 配置编辑、新建和删除确认均使用现有深色弹窗样式；
- 桌面与窄屏继续遵循 `docs/ui/approved-dashboard-demo.html` 的布局、字体、间距、配色和控件规范。

配置弹窗的视觉 Demo 已由用户确认，原型位于本地 `.superpowers/brainstorm/10887-1792546227/content/topic-config-demo.html`。`.superpowers/` 仍是本地工作记录，不纳入交付源码。

## 3. Kafka 连接与并发边界

Topic 管理操作复用当前 Topics 页面短租约会话中的 `AdminClient`。不为每次请求临时创建客户端，也不创建常驻管理客户端。

会话继续遵循现有生命周期：

1. 用户进入仪表盘后创建会话；
2. Topics 页面通过该会话读取快照和执行管理操作；
3. 页面隐藏、离开页面、切换或删除集群时释放会话；
4. 15 秒短租约与 5 秒清理机制继续作为异常退出兜底；
5. 进程关闭或会话释放必须等待进行中的管理操作结束。

同一会话的快照采集与 Topic 管理操作互斥。管理操作执行期间不启动新的快照采集；管理操作成功后立即请求新快照。该互斥只约束当前 Kafka Lens 会话，不能阻止其他客户端同时修改集群，因此所有结果仍以 Kafka 响应及后续重新查询为准。

## 4. API 设计

新增以下会话级 API：

```text
POST   /api/sessions/{sessionId}/topics
GET    /api/sessions/{sessionId}/topics/{topic}/configs
PUT    /api/sessions/{sessionId}/topics/{topic}/configs
DELETE /api/sessions/{sessionId}/topics/{topic}
```

Topic 名称作为路径段传递时必须严格进行 URL 编码和解码。所有请求继续受 256 KiB 请求体上限、Request ID、安全错误体及日志脱敏约束。

### 4.1 创建 Topic

请求字段：

- `name`：Topic 名称；
- `partitions`：正整数，默认 `1`；
- `replicationFactor`：正整数或 `null`；`null` 表示使用 Kafka 集群默认副本因子；
- `configs`：可选的白名单配置键值集合。

前后端都执行名称、数值和配置组合校验。后端不得依赖前端校验作为安全边界。创建是单 Topic 操作；只有 Kafka 返回该资源成功时，API 才返回成功。Kafka 已存在同名 Topic 时返回稳定错误码 `TOPIC_ALREADY_EXISTS`。

### 4.2 读取 Topic 配置

打开配置弹窗时实时向 Kafka 查询，不读取浏览器缓存或 SQLite 副本。响应只包含白名单字段，每项至少包含：

- 配置键；
- 当前实际生效值；
- 来源：Topic 显式覆盖值或 Broker 默认值；
- 是否可以恢复默认；
- 用于并发保护的读取版本或等价状态标识（如果底层 Kafka API 无稳定版本，则保存前重新读取并比较用户正在修改的字段）。

Demo 中出现的数值只是界面示例，正式页面不得把示例值作为真实配置或回退值。读取失败时禁止保存，并显示明确的安全错误提示。

### 4.3 更新 Topic 配置

更新请求只接受下列白名单字段。字符串值表示设置 Topic 覆盖值，`null` 表示删除该覆盖值并恢复继承 Broker 默认值：

| Kafka 配置键 | 中文名称 | 页面说明要点 |
| --- | --- | --- |
| `retention.ms` | 消息保留时间 | 消息最多保留时长；缩短可能使已有日志段更早被删除；`-1` 表示不限时。 |
| `retention.bytes` | 分区保留空间 | 每个 Partition 的保留上限，不是 Topic 总量；降低可能触发旧日志段清理；`-1` 表示不限空间。 |
| `cleanup.policy` | 清理策略 | `delete` 按保留规则删除，`compact` 按 Key 保留最新值，也可同时启用。 |
| `segment.ms` | 日志段最大时间 | 达到时间后滚动日志段，使保留和压缩策略有机会处理旧段；过小会增加文件数量。 |
| `segment.bytes` | 日志段最大大小 | 日志段达到大小后滚动；过小会增加滚动频率和文件数量。 |
| `min.insync.replicas` | 最少同步副本数 | 生产者使用 `acks=all` 时写入所需的最少同步副本数；过高可能在副本故障时阻止写入。 |
| `max.message.bytes` | 最大消息批次 | Topic 接受的最大消息批次；生产者和消费者也需使用兼容上限。 |
| `compression.type` | 压缩方式 | Topic 最终压缩方式；`producer` 表示保留生产者选择，其他选项会影响 CPU、网络和存储。 |

后端拒绝未知配置键、格式非法值和明显越界值。Kafka 仍是最终校验方；Kafka 拒绝的配置映射为安全错误码，不向客户端返回原生错误正文。

保存时只提交用户实际修改的字段。成功后重新查询 Kafka，并使用 Kafka 返回的实际值和来源刷新表单。若重新查询失败，明确提示“配置已提交，但暂时无法确认当前值”，不得把提交值伪装成已确认的实际值。

### 4.4 删除 Topic

删除请求体包含 `confirmationName`。后端要求它与路径中的 Topic 名称完全一致，否则返回校验错误。

删除操作具有以下双重保护：

- 前端要求用户手动输入完整 Topic 名称后才启用确认按钮；
- 后端拒绝删除任何以 `__` 开头的 Topic，即使客户端绕过页面直接调用 API。

删除不可撤销，且不是事务操作。只有 Kafka 返回该 Topic 删除成功时，API 才返回成功。删除请求被 Kafka 接受后，元数据传播可能延迟；页面显示“删除请求已成功，正在等待集群状态更新”，并继续刷新，直到 Topic 消失或达到有界等待时间。达到等待上限不反向报告删除失败，而是提示用户稍后刷新确认。

## 5. 页面交互

### 5.1 Topics 列表

工具栏顺序为搜索框、Topic 数量和“新建 Topic”。表格新增低视觉权重的“操作”列，包含“配置”和危险色“删除”。现有展开 Partition、Offset 汇总、陈旧数据和部分失败提示保持不变。

### 5.2 新建 Topic 弹窗

弹窗包含：

- Topic 名称；
- 分区数，默认 `1`；
- 副本因子，默认使用集群默认值；
- 8 个可选配置参数及中文作用说明与风险提示。

用户未设置的配置不发送给 Kafka。提交期间禁用重复提交；成功后关闭弹窗并刷新列表。失败时保留输入，错误显示在弹窗内。

### 5.3 配置弹窗

弹窗采用已确认的两列参数卡片布局，窄屏变为单列。每项显示中文名称、Kafka 原始键、当前值、单位、来源徽标、作用说明、风险提示和“恢复默认”。

打开弹窗后先显示加载状态；实时读取成功后才允许编辑。保存期间锁定表单，成功后重新读取并回显。关闭未保存的修改前给出离开确认。

### 5.4 删除确认弹窗

弹窗明确展示不可恢复提示、目标 Topic 名称和手动输入框。输入内容与 Topic 名称完全一致后才允许提交。内部 Topic 无删除入口；后端保护仍始终生效。

## 6. 错误处理与安全

API 至少使用以下稳定错误码，并由前端映射为明确中文文案：

- `TOPIC_ALREADY_EXISTS`；
- `TOPIC_NOT_FOUND`；
- `TOPIC_AUTHORIZATION_FAILED`；
- `TOPIC_OPERATION_TIMEOUT`；
- `INVALID_TOPIC_CONFIG`；
- `INTERNAL_TOPIC_PROTECTED`；
- 既有 `SESSION_EXPIRED`、`SNAPSHOT_IN_PROGRESS` 和 `SHUTTING_DOWN`。

错误响应和日志不得包含 Kafka 凭据、PEM、请求体、配置原始内容、broker 地址或原生 Kafka 错误正文。日志只记录稳定错误码、Request ID、集群 ID 和注册路由模板。

Kafka Lens 仍没有内置认证。启用 Topic 管理后，部署方必须更严格地限制访问范围，通过内网或带认证的 HTTPS 反向代理提供服务，并为 Kafka 账号授予最小权限。README 和发行说明需要明确：创建、删除和配置修改会真实改变 Kafka 集群。

## 7. 权限与兼容性

Kafka 账号必须具有与实际操作对应的 Topic 管理权限，例如创建、删除、读取配置和修改配置。没有权限时页面仍可保留已有只读监控能力，但管理操作显示权限错误；不能因为管理权限不足而删除或覆盖现有集群配置。

不同 Kafka 版本、托管服务和集群策略可能限制部分配置。页面不假设所有白名单参数都能修改：读取响应应保留 Kafka 报告的只读或不可用状态，禁用对应控件并说明由集群策略限制。

## 8. 测试与验收

实现遵循 TDD，先增加能因功能缺失而失败的测试，再做最小实现。

### 8.1 后端

- Topic 名称、分区数、副本因子和 8 个白名单配置的校验；
- 创建、删除、读取配置、更新配置和恢复默认；
- 已存在、不存在、无权限、超时及单资源 Kafka 失败的安全映射；
- 内部 Topic 删除保护和确认名称校验；
- 请求体限制、URL 编码、会话过期和关闭行为；
- 管理操作与快照互斥；会话释放及进程退出等待进行中的管理操作；
- 日志和错误响应不泄漏原生错误、连接地址、凭据或配置内容。

### 8.2 前端

- 新建弹窗默认值、校验、中文说明、成功刷新和失败保留输入；
- 配置弹窗的实时读取、来源徽标、加载/失败状态、单项恢复默认和保存后重新查询；
- 删除双重确认、内部 Topic 无删除入口和中文错误提示；
- 管理操作期间的重复提交保护；
- 桌面和窄屏布局，以及键盘焦点、弹窗标题和表单标签等可访问性行为。

### 8.3 E2E 与回归

E2E 只在脚本创建的一次性 Kafka 环境中执行写操作：创建专用 Topic、读取和修改配置、恢复默认、删除该 Topic，并验证列表刷新。不得对普通或未知集群创建、修改或删除资源。

完整回归继续覆盖监控、Lag 规则、会话生命周期、静态资源安全、发行脚本和双平台发行验证。

## 10. 参考依据

- Apache Kafka Topic 配置文档：Topic 配置可覆盖 Broker 默认配置，降低 `retention.ms` 可能使现有日志段在后续清理中满足删除条件。
- rust-rdkafka `AdminClient` 文档：创建、删除、读取配置和修改配置均为异步管理操作；返回结果需要按资源检查，不能只依据外层 Future 成功判断操作成功。
