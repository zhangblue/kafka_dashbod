# Kafka Lens 后台启动器设计

## 背景与目标

当前发行启动器 `start.sh` 使用 `exec` 在前台运行 Kafka Lens，终端退出会直接影响服务进程。此次修改让发行启动器提供完整、可管理的后台运行生命周期：启动后立即返回终端，记录 PID 与日志，并支持查询状态、正常停止和重启。

成功标准：

- `./start.sh` 和 `./start.sh start` 在后台启动服务并返回明确中文提示。
- PID 保存到 `data/kafka-dashboard.pid`，stdout 与 stderr 追加写入 `data/kafka-dashboard.log`。
- 支持 `status`、`stop`、`restart` 和既有 `--version`。
- 重复启动、陈旧 PID、PID 身份不匹配及并发控制均有安全行为。
- `status` 必须输出明确中文状态，不要求用户通过退出码判断“运行中”或“未运行”。
- 中文发行说明和仓库 README 与新行为一致。

## 命令接口

### 启动

以下两个命令等价：

```text
./start.sh
./start.sh start
```

启动器完成平台选择、切换发行目录、创建私有 `data/` 目录并验证进程状态后，通过 `nohup` 启动对应二进制。标准输入连接 `/dev/null`，标准输出和标准错误追加到 `data/kafka-dashboard.log`。

启动器把新进程 PID 原子写入 `data/kafka-dashboard.pid`。启动后进行短时间的有界存活确认，用于捕获 `.env` 缺失、格式错误、端口占用等立即失败；若进程提前退出，则删除本次写入的 PID 文件，返回非零并明确提示用户查看日志。确认存活后输出：

```text
Kafka Lens 已在后台启动，PID: <pid>
日志文件: <release-dir>/data/kafka-dashboard.log
```

若服务已运行，拒绝重复启动并输出已有 PID。

### 状态

```text
./start.sh status
```

状态检查读取 PID 文件、检查进程存活并核对进程命令确实指向当前发行目录对应的 Kafka Lens 二进制。

运行时输出：

```text
Kafka Lens 正在运行，PID: <pid>
```

未运行或 PID 指向的进程已经退出时输出：

```text
Kafka Lens 未运行
```

“正在运行”和“未运行”都返回成功退出码。退出码不承担状态表达职责；只有 PID 文件不可读、内容非法、无法检查进程等脚本异常才返回非零，并输出明确错误。

### 停止

```text
./start.sh stop
```

若服务未运行，输出 `Kafka Lens 未运行` 并成功返回。若 PID 对应进程存活，必须先核对进程身份；仅在确认为当前发行目录的 Kafka Lens 二进制时发送 SIGTERM。

发送 SIGTERM 后有界等待进程正常退出。进程退出后删除 PID 文件并输出：

```text
Kafka Lens 已停止
```

若等待超时，不自动发送 SIGKILL，返回非零并保留 PID 文件，提示进程仍未退出。PID 存活但身份不匹配时绝不发送信号、绝不静默删除 PID 文件，而是返回非零并提示人工核查。

### 重启

```text
./start.sh restart
```

重启顺序执行安全停止与后台启动。停止阶段出现身份不匹配、超时或脚本错误时，不继续启动新进程。成功时输出停止和启动的明确中文提示。

### 版本与非法参数

```text
./start.sh --version
```

版本查询直接前台执行对应二进制并输出版本，不要求 `.env`，不创建 PID 或日志文件。

其他参数返回非零并输出中文用法：

```text
用法: ./start.sh [start|stop|status|restart|--version]
```

## 并发与 PID 安全

启动器在变更进程状态前通过 `mkdir` 创建 `data/kafka-dashboard.lock`，利用目录创建的原子性实现跨 shell 互斥。锁只覆盖一次命令操作，使用 trap 确保正常退出或信号中断时清理；无法获取锁时返回非零并提示另一个管理操作正在执行。

PID 文件只接受纯十进制正整数。对存活 PID 执行启动、停止或状态判断前，使用目标平台可用的 `ps` 输出核对命令是否包含当前发行二进制的绝对路径。PID 不存在时可将其视为未运行并清理陈旧 PID 文件；PID 存活但身份不匹配时按错误处理，禁止误杀其他进程。

PID 文件写入采用同目录临时文件加原子重命名，避免读取到部分内容。脚本保持 `umask 077`，PID、日志、锁和数据目录均继承私有访问边界。

## 日志与数据

日志文件固定为 `data/kafka-dashboard.log`，每次启动追加而非覆盖，保留之前的诊断信息。启动器不实现日志轮转，以避免引入守护进程或平台专属依赖；发行说明明确生产部署应使用系统日志轮转或服务管理器控制日志大小。

现有 `.env` 规则保持不变：正常启动仍必须存在可读且格式正确的发行目录 `.env`，配置由 Rust 加载，父进程同名环境变量优先。启动器不读取、解析、设置或导出应用配置。

## 文档变更

`packaging/README.txt` 和仓库根 `README.md` 更新为：

- 使用 `./start.sh` 后台启动。
- 使用 `./start.sh status` 查看明确中文状态。
- 使用 `./start.sh stop` 正常停止，使用 `restart` 重启。
- 说明 PID 与日志文件位置、重复启动保护和异常处理。
- 说明启动日志采用追加模式且不会自动轮转。
- 删除“按 Ctrl-C 停止前台进程”等不再适用的描述。

`AGENTS.md` 的发行运行约定同步更新，防止后续维护恢复前台启动假设。

## 测试与验证

修改遵循 TDD，先让真实脚本行为测试因缺失功能失败，再编写最小实现。测试使用临时发行目录和可控假二进制，不操作未知系统进程。

覆盖范围：

1. 默认命令和 `start` 在后台运行、快速返回，并创建正确 PID/日志。
2. 启动参数和路径包含空格时仍保持边界。
3. 立即启动失败会删除本次 PID 并提示查看日志。
4. 重复启动被拒绝，不产生第二个进程。
5. `status` 对运行中和未运行均输出明确中文文本并成功返回。
6. PID 文件不可读或内容非法时输出错误并失败。
7. `stop` 只向身份匹配进程发送 SIGTERM，等待退出并清理 PID。
8. 未运行时 `stop` 明确提示并成功返回。
9. PID 身份不匹配时不发送信号、不删除 PID，并失败。
10. 停止超时不发送 SIGKILL，保留 PID 并失败。
11. `restart` 严格按停止后启动顺序执行，停止失败时不启动。
12. 并发锁拒绝重叠管理操作，并在命令退出后清理。
13. `--version` 维持前台查询，不要求 `.env`，不创建运行文件。
14. 非法参数显示中文用法并失败。
15. 发行构建和双平台验证适配后台启动：验证脚本通过 PID 文件管理服务，不再把 `start.sh` 的 shell PID 当作服务 PID。
