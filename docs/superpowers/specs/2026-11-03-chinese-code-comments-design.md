# 全量中文代码注释设计

## 目标

在 `AGENTS.md` 中建立可持续执行的中文注释约束，并为当前仓库的生产代码与测试代码补充中文注释。注释必须说明函数、组件、Hook 或脚本函数的职责及调用时机；关键函数调用还必须解释调用原因、顺序约束或安全边界。

本次只增加注释和开发约束，不修改程序行为、接口、数据结构、页面文案或测试语义。

## 覆盖范围

覆盖以下手写代码：

- Rust 生产代码：`backend/src/**/*.rs`
- Rust 测试与测试辅助代码：`backend/tests/**/*.rs`
- 前端生产代码：`frontend/src/**/*.{ts,tsx}`
- 前端单元测试：`frontend/src/**/*.test.{ts,tsx}`
- 浏览器验收与安全探针：`frontend/e2e/**/*`、`frontend/scripts/**/*`
- Node.js 脚本及测试：`scripts/**/*.mjs`、`tests/**/*.mjs`、`tools/**/*.mjs`
- Shell 启动、构建、验证及验收脚本：`packaging/**/*.sh`、`tools/**/*.sh`、`scripts/**/*.sh`

不处理生成目录和第三方依赖，包括 `dist/`、`frontend/dist/`、`target/`、`node_modules/`。数据库迁移 SQL、静态 HTML/CSS、JSON、锁文件和配置文件不属于函数注释范围。

## 注释规则

### 具名函数

每个具名函数、方法、React 组件、Hook 和脚本函数前都添加中文说明，至少回答：

1. 该函数负责什么。
2. 它在什么场景、流程或生命周期阶段被调用。

Rust 公共接口优先使用 `///` 文档注释；模块内部函数可使用 `///` 或紧邻定义的 `//`。TypeScript 与 TSX 导出接口、组件和 Hook 优先使用 `/** ... */`；内部函数可使用简洁的 `//`。Shell 函数使用定义前的 `#` 注释。测试函数说明它验证的业务约束、回归风险或安全边界。

注释描述意图和调用契约，不复述函数名或逐行翻译代码。生命周期、错误处理、资源所有权及安全要求应写明，而显而易见的类型和赋值无需重复说明。

### 匿名回调与闭包

普通映射、过滤、事件转发和简单测试回调不强制添加注释。匿名回调或闭包承担以下职责时必须添加中文注释：

- 并发任务、取消或退出协调。
- 数据库事务提交、回滚或替换。
- Kafka 原生资源创建、采集、管理或释放。
- 告警状态推进、重试或恢复判定。
- 会话切换、轮询启停或页面可见性处理。
- 敏感信息脱敏、安全校验或发布完整性校验。

### 关键函数调用

关键调用点前添加中文注释，解释为什么必须在此处调用以及顺序错误可能导致的后果。重点覆盖：

- 创建、停止并等待异步任务。
- 获取锁、互斥量、租约和数据库事务。
- 读取或更新配置后进行版本复核。
- Kafka 客户端、AdminClient、FFI 对象和阻塞任务的创建与析构。
- HTTP 请求、飞书通知发送、重试与超时边界。
- 页面隐藏、集群切换、组件卸载时的轮询或会话释放。
- Topic 创建、删除、配置修改以及发布上传、校验、取消草稿等不可逆或顺序敏感操作。

## 分批实施

### 开发约束

在 `AGENTS.md` 的开发与验证章节前增加“中文代码注释”小节，明确新增或修改代码必须同步维护注释，代码审查需要检查函数职责、调用时机和关键调用原因。

### Rust 代码

按领域层、数据库层、Kafka 层、会话与告警层、API 层、进程入口、测试代码的顺序处理。优先保证资源所有权、未知值语义、事务边界、原生调用和异步退出流程的注释准确。

### 前端代码

按 API、公共组件、集群和 Topic 页面、仪表盘会话、Consumer Group、Lag 规则、飞书告警、测试与 E2E 的顺序处理。重点解释 Hook 的调用生命周期、异步请求失效保护、会话释放及 Token 安全边界。

### 发布与启动脚本

为 Shell 与 Node.js 函数说明调用入口、平台选择、锁与 PID 校验、构建产物生成、哈希核验、GitHub 草稿发布及失败清理时机。

## 验收标准

- `AGENTS.md` 明确包含中文注释约束。
- 覆盖范围内每个具名函数、方法、组件、Hook 和脚本函数都有邻近的中文职责与调用时机说明。
- 关键调用点包含解释调用原因或顺序约束的中文注释。
- 测试注释描述所验证的行为或风险，不逐行复述断言。
- 不为简单匿名回调、字段映射和显而易见赋值制造噪声注释。
- 注释修改不改变任何可执行行为。
- Rust 格式化、Clippy、Rust 测试、前端测试与构建、Node.js 脚本测试、Shell 语法检查及 `git diff --check` 全部通过。
- 使用静态扫描列出具名函数，并人工复核扫描无法准确判断的宏、闭包、组件和测试辅助函数。

## 风险控制

批量注释最主要的风险是注释与真实行为不一致，以及编辑时误改可执行代码。实施时按模块小批次修改，每批检查差异只包含注释；对复杂函数先阅读调用方和测试再下结论。若函数用途或调用时机无法从代码和测试确认，先补充调查，不编造说明。
